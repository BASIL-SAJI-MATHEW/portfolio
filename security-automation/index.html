Any server with RDP or SSH open to the internet is attacked by password-guessing bots within minutes. I am Basil Saji Mathew, and I build the monitoring and automation that detects those attacks, blocks the sources and tells you what happened.

What I offer

  • Brute-force protection for Windows RDP and Linux SSH: detection, blocking and expiry, with an observe mode first.
  • Log monitoring and alerts from Windows Security Event Logs, with Discord, Telegram or Slack notifications.
  • Firewall automation including time-based allow rules and role-based access.
  • Hardening advice such as NLA, VPN or RD Gateway, lockout policy and key-only SSH.
  • Backups and recovery so an incident does not become a disaster.

Principles

Allowlist first, observe before you block, expire bans, keep an audit log, and never rely on one control alone. My tools say plainly what is and is not tested.

Frequently asked questions

How do I stop RDP brute-force attacks?

Put RDP behind a VPN or RD Gateway, restrict source addresses, require NLA, set an account lockout policy and automatically block repeat offenders. See my step-by-step guide.

Is there a fail2ban for Windows?

Fail2ban is Linux only. For Windows and Linux together you can use Portcullis, an open-source tool I built, or other Windows-focused tools.
